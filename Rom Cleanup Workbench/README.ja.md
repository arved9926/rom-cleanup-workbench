# Rom Cleanup Workbench

[English](README.md) · [Deutsch](README.de.md) · [Italiano](README.it.md) · [Español](README.es.md) · [Français](README.fr.md) · **日本語**

**画面写真付きユーザーガイド:** [PDF](<docs/Rom Cleanup Workbench - ユーザーガイド.pdf>) · [Word](<docs/Rom Cleanup Workbench - ユーザーガイド.docx>)

**動画:** [プログラムの使い方 (YouTube)](https://youtu.be/D1yXZQXg-iM)

フォルダー内の重複した ROM ファイルをゲーム名で見つけ、指示に応じて削除します。
Python 3.10 以降が必要です。ウィンドウに追加のパッケージは不要です。Linux 用のターミナル版には Textual が必要です ([ターミナル版 (Linux)](#ターミナル版-linux) を参照)。
プログラムは英語、ドイツ語、イタリア語、スペイン語、フランス語、日本語に対応しています ([言語](#言語) を参照)。

**重要:** このプログラムを元の ROM ファイルに使わないでください。ROM リポジトリのコピーを作り、整理はそのコピーに対してだけ行ってください。

## インストール

### Windows

1. **Python のインストール:** [python.org/downloads](https://www.python.org/downloads/) から Python 3.10 以降をダウンロードしてインストールします。インストーラーに "Add python.exe to PATH" があれば、チェックを入れます。ウィンドウ用の `tkinter` も含まれています。その後、新しいターミナルで確認します:

   ```powershell
   python --version
   ```

2. **プログラムのダウンロード:** Git がなければ、ZIP ファイルがいちばん簡単です。ブラウザーでは: [GitHub のページ](https://github.com/arved9926/rom-cleanup-workbench) で緑のボタン **Code** から **Download ZIP** を選び、エクスプローラーで `rom-cleanup-workbench-main.zip` を右クリックして **すべて展開...** を選び、展開したフォルダー `rom-cleanup-workbench-main` の名前を `rom-cleanup-workbench` に変えます。PowerShell で同じことをするには:

   ```powershell
   Invoke-WebRequest https://github.com/arved9926/rom-cleanup-workbench/archive/refs/heads/main.zip -OutFile rom-cleanup-workbench.zip
   Expand-Archive rom-cleanup-workbench.zip -DestinationPath .
   Rename-Item rom-cleanup-workbench-main rom-cleanup-workbench
   cd "rom-cleanup-workbench\Rom Cleanup Workbench"
   ```

   Git をインストールしてあれば、代わりにリポジトリをクローンできます:

   ```powershell
   git clone https://github.com/arved9926/rom-cleanup-workbench.git
   cd "rom-cleanup-workbench\Rom Cleanup Workbench"
   ```

   プログラムはフォルダー `Rom Cleanup Workbench` にあります。ウィンドウには追加のパッケージは不要です。Windows でターミナル版を使う場合だけ、Textual もインストールします:

   ```powershell
   python -m pip install textual==8.2.8
   ```

### Linux

1. **Python のインストール:** たいてい Python 3 はすでに入っています (`python3 --version`)。なければ Debian または Ubuntu で:

   ```bash
   sudo apt install python3 python3-venv wget unzip
   ```

   パッケージ `python3-tk` は、グラフィカルな画面のある Linux でターミナル版の代わりにウィンドウを使う場合にだけ必要です。

2. **プログラムのダウンロード:** Git がなければ、GitHub から ZIP ファイルとしてダウンロードして展開します:

   ```bash
   wget https://github.com/arved9926/rom-cleanup-workbench/archive/refs/heads/main.zip -O rom-cleanup-workbench.zip
   unzip rom-cleanup-workbench.zip
   mv rom-cleanup-workbench-main rom-cleanup-workbench
   ```

   Git をインストールしてあれば (`sudo apt install git`)、代わりにリポジトリをクローンできます:

   ```bash
   git clone https://github.com/arved9926/rom-cleanup-workbench.git
   ```

3. **仮想環境に Textual をインストール:**

   ```bash
   cd "rom-cleanup-workbench/Rom Cleanup Workbench"
   python3 -m venv ~/venvs/rom-cleanup-workbench
   ~/venvs/rom-cleanup-workbench/bin/pip install textual==8.2.8
   ```

## 使い方

### Windows

フォルダー `Rom Cleanup Workbench` でターミナル (たとえば PowerShell) を開き、ゲームのフォルダーを指定してプログラムを起動します:

```powershell
cd "rom-cleanup-workbench\Rom Cleanup Workbench"
python rom_cleanup_workbench.py "D:\Games"
```

フォルダーを指定しないと、ウィンドウが尋ねます。ターミナル版を使うには `--tui` を付けます。

### Linux

フォルダー `Rom Cleanup Workbench` に移動し、仮想環境の Python とゲームのフォルダーを指定してプログラムを起動します:

```bash
cd "rom-cleanup-workbench/Rom Cleanup Workbench"
~/venvs/rom-cleanup-workbench/bin/python rom_cleanup_workbench.py ~/roms
```

グラフィカルな画面がない場合 (SSH 経由など) は、ターミナル版が自動的に起動します。グラフィカルな画面があるとウィンドウが開きます (`python3-tk` が必要)。`--tui` を付ければ、それでもターミナル版が起動します。詳しくは [ターミナル版 (Linux)](#ターミナル版-linux) を参照してください。

### 起動後の動き

プログラムは分析ウィンドウを開き、すべてをそこに表示します。ターミナルには何も出力せず、何も尋ねません。質問、メッセージ、フォルダーの選択もウィンドウ内にプログラムの言語で表示され、Windows のポップアップになることはありません。Enter はあらかじめ選択されたボタンを押し、Esc は「いいえ」と答えます。フォルダーを指定しないと、ウィンドウがフォルダーを尋ねます。ファイルはウィンドウでの確認の後にのみ削除されます。**削除したファイルはごみ箱に移動しません。**

| オプション | 効果 |
| --- | --- |
| `--review all` | 今回の起動では `すべての削除対象` でウィンドウを開く |
| `--review problems` | 今回の起動では `要確認の削除対象` でウィンドウを開く |
| `--priority USA Europe Japan none` | 今回の実行の優先順位を指定する |
| `--delete-tag Hack Hacks Proto` | 今回の実行の削除キーワードを指定する |
| `--config file.json` | 別の設定を使う |
| `--report-only` | ウィンドウなし: レポートをターミナルに出力するだけ |
| `--yes` | ウィンドウなし: 削除対象のファイルを確認なしで削除する |
| `--all` | `--report-only` と併用: 削除対象のファイルがないゲームも表示する |
| `--tui` | ウィンドウの代わりにターミナル版を使う (グラフィカルな表示のない Linux では自動) |
| `--ascii` | ASCII 文字だけを使うターミナル版 (Linux コンソールでは自動)。`--tui` を含む |

コマンドラインオプションとそのヘルプ (`--help`) は常に英語です。

テストは `python -m unittest` で実行します。

## 分析ウィンドウ

ZIP ファイルは中身のサイズ、SHA-256 チェックサム、名前を得るために展開する必要があるため、フォルダーを選んでから結果が表示されるまで少し時間がかかることがあります。

上部の緑の行には、左に `Rom Cleanup Workbench`、右にフォルダーが表示されます。その下に、有効な優先順位とその出どころが示されます。下から 2 番目の緑の行は状態を表示し、分析中はたとえば `分析中: 2007 ファイル中 120` と表示されます。その間、中央に進行状況バーも表示されます。ウィンドウには設定の誤りなどのエラーも表示され、分析に失敗している間は何も削除できません。削除中は中央に進行状況バーが表示され、緑の行にはたとえば `削除中: 500 ファイル中 120` と表示されます。削除が終わるまで、ウィンドウは入力を受け付けません。その後、結果を報告し、フォルダーを再分析せずに削除したファイルを一覧から取り除きます。削除できなかったファイルは削除対象のまま残ります。再分析したいときは `F5` を押します。

フォルダー全体で何も削除対象になっておらず、ステータスファイルやセーブデータの疑いがあるファイルもない場合、ウィンドウの中央で `やることはありません。` が点滅します。

3 つのラジオボタンで、一覧に表示するものを決めます:

- `要確認の削除対象`: 削除対象ファイルがあり、要確認とみなされるゲームのみ (初回起動時の既定)
- `すべての削除対象`: 削除対象ファイルのあるすべてのゲーム
- `すべての ROM ファイル`: すべてのゲーム。そのファイルも `x` で削除対象にでき、読み込めない ZIP など、削除対象ファイルのない要確認のケースも表示されます。

ウィンドウは、最後に選んだ表示と確認済みのステータスファイルまたはセーブデータ (ルール 9) を、プログラムの隣の `rom_cleanup_workbench_settings.json` に記憶します。

| キー | 効果 |
| --- | --- |
| 矢印キー | 行を選択。Shift で複数行 (たとえばゲームのすべてのディスク) |
| `Tab` / `Shift+Tab` | 次 / 前のゲームへ移動。そのゲームの最初のファイルが選択される |
| `x` | ファイルを削除対象にする。ファイルはそのゲームの末尾に移動する |
| `k` | ファイルを保持する。ファイルはルールが決める位置に移動する |
| `1` `2` `3` | 表示 `要確認の削除対象`、`すべての削除対象`、`すべての ROM ファイル` |
| `Ctrl` + マウスホイール | 文字を拡大・縮小する (8～32 pt、ウィンドウを閉じるまで有効) |
| `s` | ボタン `設定...` と同じ: 言語、優先順位、削除キーワードの設定を表示・非表示にする ([設定](#設定) を参照) |
| `/` | フィルター欄に移動する |
| `Enter` | ボタン `実行...` と同じ: 確認の後に削除し、ステータスファイルまたはセーブデータの疑いがあるファイルを確認する (ルール 9) |
| `f` | ウィンドウ内で一覧の代わりに別のフォルダーを選ぶ: ダブルクリックまたは矢印でフォルダーを開くか、`パス:` にパスを入力し、`選択` または `Enter`。`キャンセル` または `Esc` では現在のフォルダーのまま |
| `r` または `F5` | 再分析する。設定も読み直す |
| `c` または `F1` | クレジットを表示する |
| `q` または `Esc` | 何も削除せずに閉じる。手動変更の後は先に確認する |

横線がゲームを区切り、ゲームは 1 つおきに濃い灰色の背景になります。`サイズ` 列は各ファイルのサイズを、Windows エクスプローラーと同様に切り上げた KB で表示します (`1,234 KB`)。`?` はサイズを読み込めなかったことを示します。サイズは分析中に読み込まれます。保持するファイルは `保持:` の下に太字で、削除するファイルは `削除対象` の下に通常の太さで表示されます。ウィンドウは黒い背景に白い Lucida Sans Typewriter 11 pt の文字を表示します。このフォントがインストールされていない場合、Windows は黙って代替フォントを選びます。手動で移動したファイルは茶色の背景になり、メモに `手動` と表示されます。行を選択している間は青く表示されます。プログラムのメモは、移動したファイルに関するものであっても変わりません。

`要確認の削除対象` は問題のないゲームを隠します。**隠れているゲームの削除対象ファイルも、削除を実行すると削除されます**。確認画面にその数が示されます。手動で変更したゲームは、フィルターで隠れていない限り常に表示されます。

### フィルター

下部の行の左にあるフィルター欄は、現在の表示を、ファイル名にパターンを含むゲームに絞り込みます。ゲームのファイルの 1 つが一致すれば、そのゲームは全体が表示されます。一覧は入力の少し後に更新されます。ファイルの内容は読み込みません。

- `*` は任意の数の文字、`?` はちょうど 1 文字を表します。`[` と `]` を含むその他の文字はそのまま文字として扱われ、大文字と小文字は区別しません。
- パターンは名前のどこに現れても構いません: `Beta`、`*Beta*`、`Mario?2` はいずれも `Super Mario 2 (Beta).nes` も見つけます。したがって `S*` は、`S` で始まる名前だけでなく、`S` を含むすべての名前を見つけます。
- `Enter`、`Tab`、下矢印で一覧に戻ります。`Esc` はフィルターを消去して一覧に戻ります。
- カーソルが欄にある間、キーは欄に入力されるだけです: `x`、`k`、`Enter`、`f`、`r`、`F5`、`Esc` は一覧の機能を実行しません。
- フィルターは `F5` の後、削除の後、別のフォルダーを選んだ後も有効なままです。保存はされません。

**フィルターは表示を変えるだけです。フィルターで隠れている削除対象ファイルも、削除を実行すると削除されます**。確認画面にその数が示されます。

### 設定

下部の行のボタン `設定...` または `s` で、`redundanz_config.json` のよく使う変更が、ファイル一覧の代わりにメインウィンドウ内に表示されます。`保存` または `キャンセル`、`Esc`、`Ctrl+E`、または `設定...` をもう一度クリックすると一覧に戻ります。その間、フィルター、表示、`実行...`、`再分析`、`フォルダー...` はロックされ、`x`、`k`、`Enter` は何もしません。隠れている一覧が変わらないようにするためです。

- **言語:** 画面の言語を決めます。 6 つの言語から選びます。新しい言語は次回の起動から適用されます。
- **優先順位:** どの地域版を他より優先するかを決めます。 最も良い地域を上に。`Beta` や `Proto` などの追加情報は `none` の後に置き、そうしたファイルが最後になるようにします (ルール 6)。項目を選んで `上へ` と `下へ` で移動し、`削除` または `Delete` キーで取り除き、一覧の下の欄と `追加` (または `Enter`) で新しい項目を加えます。
- **削除キーワード:** ゲームのどの版を必ず削除するかを決めます。 カンマ区切り。たとえば `Hack, Hacks`。これを含むファイルは削除対象になります (ルール 2)。

`保存` はファイルを書き込み、優先順位やキーワードが変わった場合はフォルダーを再分析します。手動で削除対象を変更していた場合、その変更は失われるため、プログラムは先に確認します。ファイルのその他の項目はそのまま残ります。空の地域一覧や同じ地域の重複などの誤った値は報告され、何も書き込まれず、設定は開いたままです。ファイルを読み込めない場合、設定は開きません。知らない項目を上書きしないためです。`--config` を使うと設定はそのファイルを編集し、`--priority` を使うと今回の実行ではそこで指定した優先順位が引き続き適用されます。

次の場合、ゲームは要確認とみなされます:

- どのファイルも保持されない、
- 削除対象の ZIP の内容が他のどこにもない (`警告`)、
- ZIP が破損している、暗号化されている、または読み込めない、
- ファイルがステータスファイルまたはセーブデータの疑いで保持されている (ルール 9)、
- ルールが `同点` によってのみ判定した、
- 同じバージョンの複数の ZIP の内容が異なる、
- ファイル名でゲームの表記が異なる (`Title 1-2` と `Title 12`)、
- 削除対象のファイルが、保持するファイルとファイル形式が異なる (`.nes` と `.sfc`)。

ウィンドウは `tkinter` を使います。これは Windows の通常の Python インストールに含まれています。ない場合、プログラムはそのことを報告し、何も削除しません。

## 自動整理のあとで

自動整理のあとでも、重複したゲームの版が残っていることがあります。いちばん簡単に見つける方法はフィルターです (キー `/` を押してゲーム名を入力)。そのあと、まだ削除すべきファイルを削除対象にできます。

## ターミナル版 (Linux)

同じプログラムはテキストターミナルでも動作します。たとえば SSH 経由 (PuTTY、MobaXterm)、`tmux` の中、または Linux コンソールです。同じ一覧を表示し、同じルールを適用し、`redundanz_config.json`、`rom_cleanup_workbench_settings.json`、`translations.py` をウィンドウと共有します。

Linux では、グラフィカルな表示がない場合 (SSH 経由のように `DISPLAY` も `WAYLAND_DISPLAY` も設定されていない場合) に自動で起動します。`--tui` を付けると、Windows を含むそれ以外の環境でも起動します。MobaXterm や WSL など、グラフィカルな表示はあってもターミナルを使いたい場合に使ってください。

[Textual](https://textual.textualize.io/) が必要です (8.2.8 で動作確認)。インストールとプログラムの起動方法は [インストール](#インストール) と [使い方](#使い方) を参照してください。

Textual がない場合、プログラムはそのことを伝え、何も削除しません。画面には、ウィンドウの行が上から順に並びます: フォルダーを示す緑のタイトル行、ヘルプ行、優先順位、一覧、フィルター欄、3 つの表示、緑のステータス行です。一覧では、各ゲームは太字の名前で始まり、右端までハイフンが続きます。`名前の表記が異なります` などのメモはその行に表示されます。PuTTY の 80 桁のような狭いターミナルでは、長いファイル名やメモは画面からはみ出さず、その列の中で折り返されます。`やることはありません。` はターミナル自身の点滅機能で点滅します。PuTTY では、先に点滅テキストを有効にする必要がある場合があります。質問とメッセージは一覧の上の枠に、プログラムの言語のボタン付きで表示されます。`いいえ` があらかじめ選択されています。

ヘルプ行はキーを `キー:操作` の形で示します。たとえば `x:削除  k:保持` です。ウィンドウとターミナル版のキーは同じです。

| キー | 効果 |
| --- | --- |
| 矢印キー | 行を選択。Shift で複数行 |
| `Tab` / `Shift+Tab` | 次 / 前のゲーム。その最初のファイルが選択される |
| `x` / `k` | 選択したファイルを削除対象にする / 保持する |
| `1` `2` `3` | 表示 `要確認の削除対象`、`すべての削除対象`、`すべての ROM ファイル` |
| `/` | フィルター欄に移動する |
| `Enter` | 実行: 確認の後に削除する (`実行...` と同じ) |
| `f` | ウィンドウ内で一覧の代わりに別のフォルダーを選ぶ: ダブルクリックまたは矢印でフォルダーを開くか、`パス:` にパスを入力し、`選択` または `Enter`。`キャンセル` または `Esc` では現在のフォルダーのまま |
| `s` | 設定: `Shift+上`/`Shift+下` で地域を移動、`Delete` で削除、`Ctrl+S` で保存、`Esc` で取り消し |
| `r` または `F5` | 再分析する。設定も読み直す |
| `c` または `F1` | クレジットを表示する |
| `q` または `Esc` | 何も削除せずに閉じる。手動変更の後は先に確認する |
| 質問の中で | `左`/`右` キーでボタンを選び、`Enter` で押し、`Esc` は `いいえ` と答える |

マウスも使えます: クリックで行を選択し、ホイールでスクロールし、表示やボタンもクリックできます。欄に入力した文字は、速く入力しても貼り付けても欄の中に残ります: フィルター内の `x` がファイルを削除対象にすることはありません。

**色と文字。** 256 色以上では、ターミナル版はウィンドウの色を使いますが、各ゲームの背景は黒です (縞模様なし)。ターミナルが 16 色しかない場合 (`TERM=xterm`、`TERM=linux`)、シンプルな ANSI カラーに切り替えます: 青い選択、緑のタイトル行とステータス行、手動で変更した茶色の行です。Linux コンソール、`vt100` などのターミナル、そしてロケールが UTF-8 以外の文字セットを示す場合 (たとえば `en_US` や `de_DE.ISO-8859-1`) は、ASCII 文字だけで描画します: 表示は `(*)`、枠は `+`、`-`、`|` です。`--ascii` でこれを強制できます。PuTTY は `xterm` (16 色) として名乗ります。ウィンドウと同じ色にするには、*Connection → Data → Terminal-type string* を `xterm-256color` にしてください。日本語などの他の文字体系のファイル名やテキストには、引き続きそれを表示できるターミナルとフォントが必要です。

ウィンドウとの違い: フォントはターミナルのものなので、文字の拡大縮小はありません (PuTTY では *Window → Appearance*)。また、ゲームは縞模様ではなく、ハイフンの線で始まります。16 色では緑の行の文字は黒になり、明るい緑の上でも読みやすいままです。削除中、ターミナル版はバックグラウンドで削除し、進行状況バーを表示します。終わるまですべてのキーはロックされます。ウィンドウとターミナル版は、表示と確認済みのセーブデータを同じ `rom_cleanup_workbench_settings.json` に保存します。

## 設定ファイル: `redundanz_config.json`

このファイルはプログラムの隣にあり、分析のたびに読み直されます。言語、優先順位、削除キーワードは、ウィンドウの `設定...` で変更するのが最も簡単です ([設定](#設定) を参照)。ファイルを直接編集する場合は、`region_priority` の順番を並べ替えて保存するだけで十分です:

```json
"region_priority": ["USA", "Europe", "none", "Japan", "Beta"],
"delete_tags": [],
```

ファイルに誤り (たとえばつづりの間違った項目) があると、分析は行われず、何も削除されません。付属のファイルは次のとおりです: 言語は英語、優先順位は USA、Europe、none、Japan、Beta、削除キーワードはありません。つまり地域のないファイルは日本のファイルより優先されます。ファイルや項目がない場合も、同じ既定値が使われます。

- `language`: ウィンドウ、メモ、ターミナル出力の言語 (下記参照)。
- `region_priority`: 地域と追加情報。良いものから順に並べます。`none` は地域が不明なファイルを表し、他の言語の語 (`keine`、`nessuna`、`ninguna`、`aucune`、`なし`) も使えます。`none` の後に `Beta` などの追加情報を置くと、そうしたファイルは最後になります (ルール 6)。`Beta` は `Beta 2` にも一致します。
- `region_aliases`: 地域の別表記。たとえば `Europe` に対する `Europa`。
- `delete_tags`: 削除キーワード。常に削除につながる追加情報です (ルール 2)。既定では一覧は空です。`Hack` は `Hack 2` や `Hack by Someone` にも一致しますが、`Hacks` や `Hackers` には一致しません。ハックを削除したい場合は、`Hack` と `Hacks` の両方を入力します。
- `part_tags`: バージョンの構成部分。たとえば `Disc 1`。

古いファイルには、最も低い優先度の追加情報である `low_priority_tags` がまだ含まれていることがあります。プログラムはその項目を、`region_priority` の末尾、`none` の後にあるものとして読み込みます。設定は保存時にそこへ移動し、この項目はなくなります。

### 言語

```json
"language": "de",
```

| 値 | 言語 |
| --- | --- |
| `en` | 英語 (既定) |
| `de` | ドイツ語 |
| `it` | イタリア語 |
| `es` | スペイン語 |
| `fr` | フランス語 |
| `ja` | 日本語 |

言語はウィンドウ、メモ、ターミナル出力に適用され、プログラムは起動時にそれを読み込みます: 変更した後はプログラムを閉じて再起動してください。`F5` では言語は切り替わりません。不明な値は、上で説明したとおり設定の誤りとして扱われます。ルールはどの言語でも同じように判定します。テキストは `translations.py` にあります。

日本語の場合、Lucida Sans Typewriter には日本語の文字がないため、Windows は代替フォントで文字を表示します。

## ルール

プログラムは一部のファイルを完全に無視します: それらはどこにも表示されず、削除されることもありません。

- 名前が `gamelist` で始まるファイル (大文字と小文字は区別しません)。ROM ファイルではありません。
- 隠しファイル: `.xxx` や `.DS_Store` のようにドットで始まる名前、および Windows の「隠しファイル」属性を持つファイル。

1. 最初のかっこより前のテキストが同じなら、ファイルは同じゲームです。大文字と小文字、スペース、ハイフン、アンダースコアは区別しないため、`Pac-Man` = `Pac Man` = `Pac_Man` = `PacMan` です。したがって `Title 1-2` = `Title 12` にもなります。さらに `und` = `and` = `&`、および `The Title` = `Title The` = `Title, The` = `Title` も同じとみなされます。名前の途中にある `The` は区別されます。
2. 削除キーワード (`delete_tags`、既定ではなし。たとえば `Hack` と `Hacks`) を含むファイルは、そのゲームの唯一のファイルであっても常に削除対象になります。それでも `k` でそのファイルを保持できます。
3. 残ったファイルのうち、`region_priority` で最も良い項目を持つものが保持されます。1 つのかっこ内では最も良い項目が数えられます: `(USA, Japan)` なら 2 つのうち良い方です。複数のかっこにまたがる場合は最も悪いものが数えられます: `(USA) (Beta)` は `Beta` として扱われます (ルール 6)。
4. 同じバージョンのファイルはすべて一緒に保持されます。たとえば `(Disc 1)` と `(Disc 2)`、または `.cue` と `.bin` です。それ以外はすべて削除対象になります。
5. `region_priority` にない地域は `none` として扱われます。`(Rev 1)` のような情報も同様です。
6. `Beta`、`Proto`、`Alpha` などの追加情報は、`region_priority` の `none` の後に書きます。それを含むファイルは、地域のないファイルよりも後ろ、他のすべてのファイルの後に、一覧の順で並びます: `none, Beta, Proto` なら、Beta は Proto より前です。ゲームにより良いファイルがない場合にだけ保持されます。それらの間では再び地域、次にルール 7 のバージョン、次に追加情報の後の番号で比べます: `Beta 2` は `Beta 1` に、`Beta 1` は番号のない `Beta` に勝ちます。番号は数値として比べます (`Beta 10` は `Beta 9` より上)。負けたファイルにはメモ `古いベータ版` が付きます。
7. 優先順位が同じ場合は、数値として比べて最も高いバージョン番号が勝ちます (`v1.10` は `v1.9` より上)。かっこ内では `v1.1`、`Ver 1.1`、`Version 1.1`、`Rev 1`、`Rev A` が認識され、ゲーム名の中では `Title v1.1` の形だけが認識されます (スペースの代わりに `-` や `_` でも可)。バージョンのないファイルは、バージョンのあるファイルに負けます。地域はバージョンより先に数えられます。
8. その後は、追加情報の少ないファイル、次に ZIP でないファイル、次にアルファベット順で勝ちます。レポートには `同点` と表示されます。
9. ゲームで最も大きいファイルの 1/4 より小さいファイルは、ルール 3～8 の前に取り分けられ、保持されます: ステータスファイルまたはセーブデータの可能性があるためです。そのため削除されることも、本物の ROM を押しのけることもありません。たとえば `1941.state` が `1941.zip` を押しのけることはありません。メモ列には `ステータスファイルまたはセーブデータの疑い` と表示され、そのゲームは要確認とみなされます。このようなゲームは、ファイルが 1 つも削除対象でなくても 3 つの表示すべてに現れます。削除を実行すると、プログラムは残っている疑いのあるファイルをすべて正当なものとして確認します: それらはそのまま残り、引き続き削除されることはなく、`F5` の後や再起動後も `要確認の削除対象` と `すべての削除対象` に表示されなくなります。確認画面にその数が示されます。プログラムはそれらをパスとサイズとともに `rom_cleanup_workbench_settings.json` に記録します。サイズが変わると、そのファイルは再び疑いの対象になります。何も削除対象になっていない場合、`Enter` は何も削除せずにそれらを確認することを提案します。ZIP は展開後のサイズで数えます。同じバージョンの大きな通常ファイルの隣にある小さな通常ファイル (`.bin` の隣の `.cue` など) や、`delete_tags` や破損した ZIP のために削除対象になったファイルには適用されません。それでも `x` でファイルを手動で削除対象にできます。

## ZIP ファイル

すべての ZIP ファイルは、ゲームの唯一のファイルであっても完全に読み込まれます。その内容は SHA-256 でゲームの他のファイルと比較されます。

- **保持するファイルと内容が同じ:** ZIP ファイルは削除対象になり、レポートに同じ内容のファイルが示されます。
- **選択の後に ZIP と通常ファイルが残った場合:** ZIP が `(Disc 1)` のような構成部分を含む唯一のファイルである場合、または読み込めない場合は、内容が異なっていても ZIP は常に削除対象になります。
- **内容の異なる同一バージョンの ZIP が複数:** すべて保持され、レポートでそのことが示されます。
- **削除対象だが、内容がどの保持ファイルにもない:** レポートに `警告` と表示されます。ファイルは削除対象のままです。
- **ZIP の名前に地域やバージョンがない:** ZIP 内のファイルが同じゲーム名であれば、その情報はそれらのファイルから取得されます。
- **破損または暗号化された ZIP:** ゲームの唯一のファイルであっても、常に削除対象になります。暗号化された ZIP の内容は確認しません。
- **ロックされた ZIP または不明な方式 (たとえば Deflate64):** これはファイルの状態について何も示しません。ゲームの通常ファイルがなければ保持され、レポートに示されます。

## Claude Code で開発を続ける

このプログラムはフリーソフトウェアです。リポジトリをクローンし、自分でプログラミングしなくても [Claude Code](https://claude.com/claude-code) で開発を続けられます。このプログラムもそうして書かれました。

1. Claude Code をインストールします。Claude のサブスクリプションまたは Claude API のアカウントが必要です。Windows では PowerShell で:

   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```

   Linux では:

   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```

2. リポジトリをクローンし、その中で Claude Code を起動します:

   ```bash
   git clone https://github.com/arved9926/rom-cleanup-workbench.git
   cd rom-cleanup-workbench
   claude
   ```

3. 何を変えたいかを自分の言葉で説明します。たとえば "ZIP ファイルだけを表示するオプションを追加して"。Claude Code はコードを読んで変更を提案し、ファイルを変更したりコマンドを実行したりする前に確認します。そのあとテストを実行させ (フォルダー `Rom Cleanup Workbench` で `python -m unittest`)、変更をコレクションのコピーで試してください。

これまでの変更の計画は `docs/` にあります。変更を配布する場合は、それも GPL のもとで公開する必要があります。
