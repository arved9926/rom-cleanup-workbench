# Rom Cleanup Workbench

[English](README.md) · [Deutsch](README.de.md) · [Italiano](README.it.md) · [Español](README.es.md) · [Français](README.fr.md) · **日本語**

**画面写真付きユーザーガイド:** [PDF](<docs/Rom Cleanup Workbench - ユーザーガイド.pdf>) · [Word](<docs/Rom Cleanup Workbench - ユーザーガイド.docx>)


フォルダー内の重複した ROM ファイルをゲーム名で見つけ、指示に応じて削除します。
Python 3.10 以降が必要です。ウィンドウに追加のパッケージは不要です。Linux 用のターミナル版には Textual が必要です ([ターミナル版 (Linux)](#ターミナル版-linux) を参照)。
プログラムは英語、ドイツ語、イタリア語、スペイン語、フランス語、日本語に対応しています ([言語](#言語) を参照)。

**重要:** このプログラムを元の ROM ファイルに使わないでください。ROM リポジトリのコピーを作り、整理はそのコピーに対してだけ行ってください。

## インストール

GitHub アカウントは不要です。コマンドは 1 つずつ枠に入っています。そのとおりに入力して Enter を押してください。

### Windows

コマンドはすべて PowerShell に入力します。

1. **Python がインストールされているか確認する:**

   ```powershell
   python --version
   ```

   - **`Python 3.10` 以上と表示された場合:** Python はあります。手順 2 へ進みます。

   - **エラーまたは古いバージョンが表示された場合:** [python.org/downloads](https://www.python.org/downloads/) から Python 3.10 以降をダウンロードしてインストールします。インストーラーに「Add python.exe to PATH」があれば、チェックを入れます。ウィンドウ用の `tkinter` も含まれます。その後、新しい PowerShell ウィンドウを開いて、もう一度確認します。

2. **Git がインストールされているか確認する:**

   ```powershell
   git --version
   ```

   - **バージョン番号 (たとえば `git version 2.47.0`) が表示された場合:** Git でプログラムをダウンロードします:

     ```powershell
     git clone https://github.com/arved9926/rom-cleanup-workbench.git
     ```

   - **エラーが表示された場合:** プログラムを ZIP ファイルとしてダウンロードします。ブラウザーでは [GitHub のページ](https://github.com/arved9926/rom-cleanup-workbench) で **Code**、次に **Download ZIP** を選び、ファイルを右クリックで展開し (**すべて展開...**)、フォルダー `rom-cleanup-workbench-main` の名前を `rom-cleanup-workbench` に変更します。または PowerShell で 1 つずつ:

     ```powershell
     Invoke-WebRequest https://github.com/arved9926/rom-cleanup-workbench/archive/refs/heads/main.zip -OutFile rom-cleanup-workbench.zip
     ```

     ```powershell
     Expand-Archive rom-cleanup-workbench.zip -DestinationPath .
     ```

     ```powershell
     Rename-Item rom-cleanup-workbench-main rom-cleanup-workbench
     ```

3. **プログラムのフォルダーに移動する:**

   ```powershell
   cd "rom-cleanup-workbench\Rom Cleanup Workbench"
   ```

   ウィンドウには追加のパッケージは不要です。Windows でターミナル版を使う場合だけ、Textual も追加でインストールします:

   ```powershell
   python -m pip install textual==8.2.8
   ```

### Linux

コマンドはすべてターミナルに入力します。例は Debian と Ubuntu 用です。

1. **Python がインストールされているか確認する:**

   ```bash
   python3 --version
   ```

   - **`Python 3.10` 以上と表示された場合:** Python はあります。手順 2 へ進みます。

   - **エラーまたは古いバージョンが表示された場合:** Python をインストールします:

     ```bash
     sudo apt install python3 python3-venv
     ```

   パッケージ `python3-tk` は、グラフィカル表示のある Linux でターミナル版ではなくウィンドウを使いたい場合にだけ必要です。

2. **Git がインストールされているか確認する:**

   ```bash
   git --version
   ```

   - **バージョン番号が表示された場合:** Git でプログラムをダウンロードします:

     ```bash
     git clone https://github.com/arved9926/rom-cleanup-workbench.git
     ```

   - **エラーが表示された場合:** プログラムを ZIP ファイルとしてダウンロードして展開します。1 つずつ:

     ```bash
     sudo apt install wget unzip
     ```

     ```bash
     wget https://github.com/arved9926/rom-cleanup-workbench/archive/refs/heads/main.zip -O rom-cleanup-workbench.zip
     ```

     ```bash
     unzip rom-cleanup-workbench.zip
     ```

     ```bash
     mv rom-cleanup-workbench-main rom-cleanup-workbench
     ```

3. **プログラムのフォルダーに移動する:**

   ```bash
   cd "rom-cleanup-workbench/Rom Cleanup Workbench"
   ```

4. **仮想環境に Textual をインストールする:**

   ```bash
   python3 -m venv ~/venvs/rom-cleanup-workbench
   ```

   ```bash
   ~/venvs/rom-cleanup-workbench/bin/pip install textual==8.2.8
   ```

## 使い方

### Windows

フォルダー `Rom Cleanup Workbench` でターミナル (たとえば PowerShell) を開き、ゲームのフォルダーを指定してプログラムを起動します:

```powershell
cd "rom-cleanup-workbench\Rom Cleanup Workbench"
```

```powershell
python rom_cleanup_workbench.py "D:\Games"
```

フォルダーを指定しない場合、プログラムは最後に選んだフォルダーを再び開きます。`roms` フォルダーならその概要を、それ以外のフォルダーは直接開きます。初回はウィンドウがフォルダーを尋ねます。ターミナル版を使うには `--tui` を付けます。

### Linux

フォルダー `Rom Cleanup Workbench` に移動し、仮想環境の Python とゲームのフォルダーを指定してプログラムを起動します:

```bash
cd "rom-cleanup-workbench/Rom Cleanup Workbench"
```

```bash
~/venvs/rom-cleanup-workbench/bin/python rom_cleanup_workbench.py ~/roms
```

グラフィカルな画面がない場合 (SSH 経由など) は、ターミナル版が自動的に起動します。グラフィカルな画面があるとウィンドウが開きます (`python3-tk` が必要)。`--tui` を付ければ、それでもターミナル版が起動します。詳しくは [ターミナル版 (Linux)](#ターミナル版-linux) を参照してください。

### 起動後の動き

プログラムは分析ウィンドウを開き、すべてをそこに表示します。ターミナルには何も出力せず、何も尋ねません。質問、メッセージ、フォルダーの選択もウィンドウ内にプログラムの言語で表示され、Windows のポップアップになることはありません。Enter はあらかじめ選択されたボタンを押し、Esc は「いいえ」と答えます。フォルダーを指定しないと、ウィンドウがフォルダーを尋ねます。ファイルはウィンドウでの確認の後にのみ削除されます。**削除したファイルはごみ箱に移動しません。**

| オプション | 効果 |
| --- | --- |
| `--review all` | 今回の起動ではウィンドウを `削除対象` で開きます |
| `--review problems` | 今回の起動ではウィンドウを `要確認` で開きます |
| `--priority USA Europe Japan none` | 今回の実行の優先順位を指定する |
| `--delete-tag Hack Hacks Proto` | 今回の実行の削除キーワードを指定する |
| `--config file.json` | 別の設定を使う |
| `--report-only` | ウィンドウなし: レポートをターミナルに出力するだけ |
| `--yes` | ウィンドウなし: 削除対象のファイルを確認なしで削除する |
| `--scan-all` | ウィンドウなし: 指定した `roms` フォルダーのすべてのプラットフォームフォルダーをスキャンし、そのデータベースに保存する。何も削除しない |
| `--deep-scan` | `--scan-all` と一緒に: ディープスキャン。新しいファイルと変更されたファイルだけでなく、すべてのファイルを読み直す (`--full` も引き続き使える) |
| `--write-gamelists` | ウィンドウなしで: 指定した `roms` フォルダーのすべてのプラットフォームの `gamelist.xml` をデータベースから書き込みます。以前のファイルはそれぞれコピーとして残ります |
| `--all` | `--report-only` と併用: 削除対象のファイルがないゲームも表示する |
| `--tui` | ウィンドウの代わりにターミナル版を使う (グラフィカルな表示のない Linux では自動) |
| `--ascii` | ASCII 文字だけを使うターミナル版 (Linux コンソールでは自動)。`--tui` を含む |

コマンドラインオプションとそのヘルプ (`--help`) は常に英語です。

テストは `python -m unittest` で実行します。

## コレクション: 多数のプラットフォームとデータベース

ふつうゲームは、`roms/nes`、`roms/snes`、`roms/n64` のように、プラットフォームごとに分けて共通のフォルダーに入っています。この `roms` フォルダーを選ぶと、プログラムはすべてのプラットフォームの **概要** を表示します。それ以降は常に最後に選んだフォルダーで起動し、`roms` フォルダーならその概要で起動します。すでにデータベースがあるフォルダー、または自身には ROM ファイルがなくサブフォルダーがあるフォルダーを `roms` フォルダーとみなします。`info.txt`、画像、PDF などの付属ファイルは ROM ファイルとして数えません。それ以外のフォルダーは、これまでどおりデータベースなしで単独で分析されます。

**データベース。** 初めて開くとき、プログラムは `roms` フォルダーに隠しフォルダー `.rom_cleanup_workbench` を作り、その中に SQLite データベースを置きます。コレクションに書き込むのはこれだけです。各スキャンの結果 (ファイル、サイズ、更新日時、ZIP の内容とチェックサム) が保存されます。プラットフォームを開くと、プログラムはそこから判定を一瞬で計算し直します。そのため設定の変更は、再スキャンしなくてもすぐに反映されます。さらに、手動の変更 (`k`/`x`)、確認済みのステータスファイルとセーブデータ、各プラットフォーム固有の設定も保存されます。基準になるのはフォルダーです: プラットフォームのフォルダーがなくなると、概要を開いたときに、固有の設定や `ゲームなし` を含め、データベースがそのフォルダーについて持っていた情報をすべて削除します。同じ名前の新しいフォルダーは最初からやり直しになります。ネットワークドライブが接続されていないなど、`roms` フォルダー自体に到達できない場合は、何も削除しません。

**概要** には、プラットフォームごとに、ファイル数、ゲーム数、削除対象のファイル数、要確認のゲーム数、完全に削除されるゲーム数 (ファイルが 1 つも残らないゲーム)、最後のスキャン、状態 (`未スキャン`、`最新`、またはその後ファイルが追加・削除・変更された場合は `変更あり`) が表示され、その下に合計が表示されます。合計とプラットフォームの間は線で区切られます。状態 `変更あり` は黄色で表示されます (ウィンドウでは行全体)。見出しの `プラットフォーム`、`ファイル`、`ゲーム`、`削除対象`、`要確認`、`完全に削除`、`情報`、`gamelistの問題` をクリックするとその列で並べ替え、もう一度クリックすると逆順になります。矢印が向きを示し、合計は下に残り、数値のないプラットフォームは最後になり、選択は保存されます。

| ボタン | キー | 効果 |
| --- | --- | --- |
| `開く` | `Enter` | 選択中のプラットフォームをいつもの一覧で開く (ダブルクリックでも可) |
| `スキャン` | `r` または `F5` | 選択中のプラットフォームをスキャンして開く |
| `すべてスキャン` | `a` | すべてのプラットフォームを順にスキャンする。それぞれすぐに保存され、その数値はすぐに概要に表示される。`キャンセル` しても終わった分は残る。何も削除しない |
| `ディープスキャン` | `d` | スキャンとすべてスキャンのスイッチ (赤い点): 新しいファイルと変更されたファイルだけでなく、すべてのファイルを読み直す |
| `空を隠す` | `h` | スイッチ (赤い点): ゲームファイルのないフォルダーを隠す。たとえば `bios` や `info.txt` だけのフォルダー。付属ファイルはゲームファイルとして数えない。選択は保存される |
| `フォルダー...` | `f` | 別の `roms` フォルダーを選ぶ |
| | `n` | 選択中のフォルダーを `ゲームなし` にする、またはそれを解除する (下記参照) |
| | `w` | 選択中のプラットフォームの `gamelist.xml` をデータベースから書き込む (確認の後) |
| | `m` | 選択中のプラットフォームの使われていないメディアファイルを削除する (確認の後、下記参照) |
| | `q` または `Esc` | プログラムを閉じる |

キーはウィンドウとターミナル版で同じです。表の上の行に主なキーが示され、`F1` または `?` ですべてのキーが表示されます。

**スキャン。** スキャンは通常は速く、新しいファイルと変更されたファイル (名前、サイズ、変更日時で判断) だけを読み、それ以外はデータベースから取ります。`ディープスキャン` ではすべてのファイルを読み直します。一覧で `F5` を押すと、開いているプラットフォームをすばやくスキャンします。実行すると、削除や名前変更したファイルがすぐに記録されるので、その後に新しいスキャンは不要です。

**概要に戻る**には、一覧で `Esc`、`q`、または `概要` ボタンを使います。ターミナル版では `o` も使えます。概要で `Esc` または `q` を押すとプログラムが終了するので、完全に終えるには 2 回押します。

**gamelist.xml。** プラットフォームのフォルダーに `gamelist.xml` (EmulationStation、RetroPie、Batocera、ES-DE、ARRM) があれば、スキャンはそれを読み込み、確認できる内容をデータベースに取り込みます: 名前、説明、評価、日付、開発元、発売元、ジャンル、プレイ人数、地域、お気に入り、プレイ時間、画像や動画などのメディアへの参照をカテゴリーごとに (`wheel` と `logo` は同じファイルを指していても別々のままです)。その他の項目はすべてそのまま引き継がれます。`<genreid>` の数値 (たとえば `1538`) は Recalbox のジャンル一覧によるもので、メインジャンル × 256 + サブジャンルです。つまり `1538` = `0x0602` = スポーツ、サブジャンル 2「スポーツシミュレーション」です。ARRM などのツールがスクレイピング時に書き込みます。ゲーム情報ではこの数値が名前付きで表示されます。たとえば「1538 – スポーツシミュレーション (スポーツ)」です。ScreenScraper のジャンル番号とは関係ありません。プラットフォームにジャンル番号があると、一覧に `ジャンル` 列が表示されます。その見出しをクリックするとゲームをジャンル順に並べ (Recalbox 一覧の順、ジャンルのないゲームは最後、同じジャンル内は名前順)、もう一度クリックするか `ファイル` をクリックすると名前順に戻ります。選択は保存されます。編集フォームでは `ジャンル（Recalbox一覧）` で Recalbox のすべてのジャンルから番号を選びます。テキスト欄 `ジャンル` はその隣で自由に使えます。手動で選んだ番号は、再インポートしても保持されます。ROM がプラットフォームのフォルダーにないエントリーと、存在しないファイルへの参照は取り込まれず、問題として数えられます。`/home/pi/RetroPie/roms/nes/…` のような別のコンピューターのパスは、プラットフォームのフォルダーに書き換えられ、注意として数えられます。ファイルは変更されたときだけ読み込まれます。変更された `gamelist.xml` は状態を `変更あり` にします。ファイル自体は変更されません。保存先はデータベースであり、`gamelist.xml` ではありません: ファイルが削除されても情報は残ります。一方、ROM やメディアがフォルダーからなくなると、データベースからも消え、削除された ROM はその情報も一緒に失います。概要の `情報` には情報を持つ ROM の数が、`gamelistの問題` には取り込まれなかったものが表示されます。プラットフォーム名の後ろには、取り込まれたエントリー数が灰色で表示されます。ファイルが壊れている場合は何も取り込まず、それまでの内容が残ります。

**プラットフォームのフォルダー外の gamelist.xml とメディア。** プラットフォームのフォルダーに独自の `gamelist.xml` がない場合、Workbench はフロントエンドが保存する場所を次の順に探します: `~/ES-DE/gamelists/<プラットフォーム>/` (ES-DE)、`~/.emulationstation/gamelists/<プラットフォーム>/` (EmulationStation、RetroPie)、Linux では `/etc/emulationstation/gamelists/<プラットフォーム>/`。プラットフォームのフォルダー名がシステム名として使われます。`%ROMPATH%/nes/…` のようなパスは、プラットフォームのフォルダーを基準にします。灰色の行、レポート、書き込み前の確認にその場所が表示されます。書き込みは同じ場所に行われ、バックアップもそこに置かれます。Workbench はさらに `~/ES-DE/downloaded_media/<プラットフォーム>/` (または ES-DE の設定で選んだメディアフォルダー)、`~/.emulationstation/downloaded_media/` と `downloaded_images/` でもメディアを探します。コレクション外のこうしたメディアは表示され `gamelist.xml` に書き込まれるだけで、削除や名前の変更は決してされません。

**サブフォルダー内のメディア。** スキャンのたびに、Workbench はプラットフォームのすべてのサブフォルダーで、`gamelist.xml` がまだ挙げていない画像、動画、説明書も探します。名前から明確にわかるものだけが割り当てられます: カテゴリーごとのフォルダーに ROM の名前で置かれたもの (`wheel/10yard.png`、`marquees/10yard.png`)、または任意のフォルダーにある ROM 名・区切り文字 (`-`、`.`、`_`)・カテゴリーの組み合わせ (`downloaded_images/10yard-wheel.png`、`game.image.jpg`)。複数の ROM に当てはまる場合は、最も長い名前が優先されます (`sf2ce-image.png` は `sf2.zip` ではなく `sf2ce.zip` のものです)。似ていることによる割り当てはありません。明確でないものは ROM なしのままです。`gamelist.xml` にエントリーのないゲーム ROM には、最初のかっこより前の名前で空のエントリーが作られます。BIOS ファイル (かっこ内の `BIOS`、または `neogeo`、`pgm`、`skns` などの既知の名前) はゲームではないとみなされ、メディアは割り当てられません。プラットフォーム名の後ろには、割り当てられたメディアの数と ROM なしのままのメディアの数が灰色で表示されます。`情報` は、メディアが見つかった空のエントリーも数えます。

**使われていないメディアファイルを削除する。** `m` (プラットフォーム内、または概要で選択中のプラットフォームに対して) は、もう何にも使われていない画像、動画、説明書を探します: フォルダー内にその名前の ROM がなく、どの `gamelist.xml` からも参照されていないもの、たとえば Workbench の外で削除された ROM の画像です。探すのはプラットフォームのフォルダー内のメディアフォルダーだけです。つまり、名前がカテゴリーであるフォルダー (`images`、`videos`、`marquees`、`wheel`、`manuals` …) または `media`、`downloaded_images`、`downloaded_media`、`artwork`、`boxart`、`covers` です。プラットフォームのフォルダー直下のファイル、その他のサブフォルダー (ゲームごとのフォルダーなど) のファイル、コレクション外の ES-DE や RetroPie のメディアフォルダーのファイルには決して触れません。その前に Workbench はフォルダーと変更された `gamelist.xml` を読み直します。`gamelist.xml` が読めない場合は何も削除しません。確認には、数、サイズ、最初のいくつかのファイルが表示されます。削除したファイルはごみ箱に入りません。どのメディアに ROM がないかは、事前に `g` のレポートで確認できます。

**ゲーム情報、名前、レポート。** `gamelist.xml` の名前はファイルではなくゲーム全体のものです: ゲームの見出しには、保持するファイルの名前と、その後ろのかっこ内に私たちのタイトルが表示されます。たとえば `10-Yard Fight (10yard)` です。両者が同じか名前がない場合は、私たちのタイトルだけが表示されます。ゲーム名の行の `メモ` 列には、問題があればその後に、評価、プレイ人数、発売年が表示されます。たとえば `★ 4.5 · 1-2 人 · 1991` (`--ascii` では `* 4.5 - 1-2 人 - 1991`) です。これらは保持するファイルから、そのファイルにない場合はゲームの別のファイルから取られます。BIOS ファイルと `n` で指定したファイルは、`メモ` 列に `ゲームではない` と表示されます。`Enter` (ウィンドウではファイルのダブルクリックでも) は、一覧の代わりにゲームについてわかっていることをすべて表示します: 判定付きのファイル、説明・評価 (x / 5 で)・日付・開発元・プレイ時間・お気に入りなどの項目、`gamelist.xml` のその他の項目、カテゴリーごとのメディア。プレビュー画像は意図的にありません。`g` は gamelist レポートを表示します: 取り込まれなかったものとその理由、注意、情報のない ROM、ROM のないメディア、ゲームではないファイルです。`n` は選択したファイルを `ゲームではない` にする、またはそれを解除します。後の `gamelist.xml` で変わることはありません。ファイルを残すか削除するかは、引き続きルールが判定します。`gamelist.xml` とメディアの概要は、プラットフォームの行の下の別の行に灰色で表示されます。

**削除と名前の変更はメディアも一緒に扱います。** `実行...` が ROM を削除すると、そのメディアも一緒に削除されます。`gamelist.xml` からの画像、動画、説明書もサブフォルダーのものも同様です。削除前の確認にはその数が表示されます。残る ROM も使っているメディアは残ります。削除された ROM は、お気に入りやプレイ時間を含めてその情報も失います。`実行...` が名前の前の番号を取り除くと、名前が古い ROM 名で始まるメディアも一緒に名前が変わります (`01 - Alpha (USA)-image.png` は `Alpha (USA)-image.png` になります)。`gamelist.xml` 自体は変更されません。

**ゲーム情報の編集。** ゲーム情報で `e` を押すと、ファイルのフォームが開きます: 名前、並べ替え名、説明、評価 (0～5 の星、3.5 なども可)、発売日 (`YYYY`、`YYYY-MM`、`YYYY-MM-DD`)、開発元、発売元、ジャンル、プレイ人数、地域、言語、さらにお気に入り、非表示、子ども向けです。プレイ時間、プレイ回数、ID は、フロントエンドとスクレイパーが管理するとおりに残ります。`Ctrl+S` または `保存` で保存し、`Esc` または `キャンセル` で保存せずにゲーム情報に戻ります。誤った値は指摘され、フォームは開いたままです。変更した項目にはゲーム情報で `✎` が付きます。`gamelist.xml` を再インポートしても、それらはそのまま残ります。空のエントリーは、編集すると本当のエントリーになります。`gamelist.xml` を書き込むと、変更も一緒に書き込まれます。

**gamelist.xml の書き込み。** Workbench は、求められたときだけ、プラットフォームの `gamelist.xml` をデータベースから書き直します: プラットフォーム内または概要で選択中のプラットフォームに対して `w`、すべてに対して `--write-gamelists`。ファイルを削除したクリーンアップの後、プラットフォームに `gamelist.xml` があれば書き込みを提案します。その前に、以前のファイルは `gamelist.xml.<日付_時刻>.bak` として保存されます。最新の 3 つのコピーが残り、それより古いものは削除されます。新しいファイルはまず別の名前で作られ、それから一度に古いファイルと置き換わるので、書きかけのファイルが残ることはありません。すべてのゲームを含み、空のエントリーのゲームも含みますが、BIOS ファイルなどゲームではないものは含みません。さらに、既知のすべての項目、カテゴリーごとのメディア (2 つのカテゴリーにあるファイルは 2 回記載)、ID、その他すべての項目を読み込んだとおりに含みます。既定値と同じ値は、EmulationStation と同様に省かれます。`<provider>` ブロックにはソフトウェアとして `RCW` (Rom Cleanup Workbench) と私たちの GitHub ページが記載されます。システムはそのままです。その後、ファイルは読み込み済みとみなされます。

**ゲームのないフォルダー。** `bios` や `saves` のようなフォルダーにはゲームがありません。`n` は選択中のフォルダーを `ゲームなし` にします: スキャンされず (`すべてスキャン` や `--scan-all` でも)、開かれず、合計に数えられず、`空を隠す` で非表示になります。データベースがそのフォルダーについて持っていた情報は削除されます。もう一度 `n` を押すと解除され、フォルダーは `未スキャン` になります。そのためのボタンは意図的にありません。

**手動の変更** (`k`/`x`) は、実行するかプラットフォームを再スキャンするまで、閉じた後も保存されます。ファイルが変わると、その手動の変更は無効になります。

**プラットフォームごとの設定。** プラットフォームを開いているとき、設定の上部に `全般設定` または `NES 専用の設定` が表示されます。プラットフォーム専用を選ぶと、優先順位、削除キーワード、通常ファイルと ZIP の選択はこのプラットフォームだけに適用されます。それらはデータベースに保存され、他のすべてのプラットフォームには `redundanz_config.json` が標準として残ります。新しい専用の設定は標準の値から始まり、`全般設定` に戻すと破棄されます。設定の見出しの下の行に保存先が示されます: `redundanz_config.json`、またはプラットフォーム専用の場合はコレクションのデータベースです (言語は `redundanz_config.json` に残ります)。言語は常にすべてに適用されます。概要では、そのようなプラットフォームの名前の後に `*` が付きます。

**ウィンドウなし**では、`--scan-all` ですべてのプラットフォームをスキャンできます。たとえば夜間に:

```powershell
python rom_cleanup_workbench.py "D:\roms" --scan-all
```

`--deep-scan` を付けると、すべてのファイルを読み直します。この方法で何かが削除されることはありません。

## 分析ウィンドウ

ZIP ファイルは中身のサイズ、SHA-256 チェックサム、名前を得るために展開する必要があるため、フォルダーを選んでから結果が表示されるまで少し時間がかかることがあります。

上部の緑の行には、左に `Rom Cleanup Workbench`、右にフォルダーが表示されます。その下には緑で `プラットフォーム:` と開いているフォルダーの名前が太字で表示され、プラットフォームに固有の設定があれば概要と同じく後ろに `*` が付きます。その後に空行が続きます。右側にはその画面の主なキーが表示され、一覧では `x 削除`、`k 保持`、`Enter ゲーム情報`、`F12 クリーンアップを実行`、`F1 / ? ヘルプ: その他のキー` です。`F1` または `?` は、一覧の代わりにすべてのキーをテーマ別に表示し、`Esc`、`F1`、`?` で再び閉じます。概要ではどちらも概要のキーを表示し、その下の `知っておくと便利` に、状態、スキャン、ディープスキャンの意味を表示します。現在の優先順位は設定で確認できます。概要では `コレクション` という語も緑で表示されます。下から 2 番目の緑の行には状態が表示され、分析中はたとえば `分析中: 2007 ファイル中 120` です。その間、中央に進行状況バーも表示されます。ウィンドウには設定の誤りなどのエラーも表示され、分析が失敗している間は何も削除できません。削除中は中央に進行状況バーが表示され、緑の行にはたとえば `削除中: 500 ファイル中 120` と表示されます。削除が終わるまで、ウィンドウは入力を受け付けません。その後、結果を知らせ、フォルダーを再分析せずに削除したファイルを一覧から取り除きます。削除できなかったファイルは削除対象のままです。必要なら `F5` でフォルダーを再分析します。

フォルダー全体で何も削除対象になっておらず、ステータスファイルやセーブデータの疑いがあるファイルもない場合、ウィンドウの中央で `やることはありません。` が点滅します。

4 つのラジオボタンで、一覧に表示するものを決めます:

- `要確認`: 削除対象ファイルがあり、要確認とみなされるゲーム、つまり意図せず何かが失われるおそれのあるゲームのみ (初回起動時の既定)
- `削除対象`: 削除対象ファイルがあるすべてのゲーム
- `完全に削除`: ファイルが 1 つも残らないゲーム。たいていは削除キーワードがそのすべてのファイルに当てはまるためです (たとえば削除キーワード `Japan` での `Ikaruga (Japan).cdi`)。削除キーワードが多くを拾いすぎていないか確認する価値があります。確認画面では、これらのゲームを分けて示します: 指定どおり削除キーワードによるものと、それ以外です。
- `すべてのゲーム`: すべてのゲーム。たとえばゲーム情報を見て回ったり、ジャンル順に並べたりするためです。そのファイルも `x` で削除対象にでき、読み込めない ZIP など、削除対象ファイルのない要確認のケースも表示されます。

**ゲーム名のみ。** `ゲーム名のみ` スイッチ (ウィンドウでは表示切り替えの隣、ターミナルではフィルター欄の右) または `z` で、一覧をゲーム名の行だけに折りたたみ、区切り線もなくします: プラットフォームにどのゲームがあるかを、`メモ` 列の評価、プレイ人数、年とともに一目で確認できます。フィルター、表示切り替え、ジャンル順の並べ替えはそのまま使えます。`Tab` はゲームからゲームへ移動し、`Enter` は保持するファイルのゲーム情報を表示します。`x` と `k` はファイルにだけ作用します。ウィンドウでは、ダブルクリックまたは右矢印で 1 つのゲームを展開します。もう一度 `z` を押すとファイルが再び表示されます。選択は保存されます。

ウィンドウは、最後に選んだ表示と確認済みのステータスファイルまたはセーブデータ (ルール 9) を、プログラムの隣の `rom_cleanup_workbench_settings.json` に記憶します。

| キー | 効果 |
| --- | --- |
| 矢印キー | 行を選択。Shift で複数行 (たとえばゲームのすべてのディスク) |
| `Tab` / `Shift+Tab` | 次 / 前のゲームへ移動。そのゲームの最初のファイルが選択される |
| `x` | ファイルを削除対象にする。ファイルはそのゲームの末尾に移動する |
| `k` | ファイルを保持する。ファイルはルールが決める位置に移動する |
| `1` `2` `3` `4` | 表示 `要確認`、`削除対象`、`完全に削除`、`すべてのゲーム` |
| `z` | ゲーム名だけを表示する、またはファイルを再び表示する (`ゲーム名のみ` スイッチと同じ) |
| `Ctrl` + マウスホイール | 文字を拡大・縮小する (8～32 pt、ウィンドウを閉じるまで有効) |
| `s` | ボタン `設定...` と同じ: 言語、優先順位、削除キーワード、ZIP か通常ファイルかの設定を表示・非表示にする ([設定](#設定) を参照) |
| `/` | フィルター欄に移動する |
| `F12` | `実行...` ボタンと同じ: 確認の後に削除し、保持するファイル名の前の番号を取り除き (ルール 10)、ステータスファイルまたはセーブデータの疑いのあるファイルを確認します (ルール 9) |
| `f` | ウィンドウ内で一覧の代わりに別のフォルダーを選ぶ: 矢印でフォルダーを開き、ダブルクリックですぐに選ぶか、`パス:` にパスを入力し、`選択` または `Enter`。`キャンセル` または `Esc` では現在のフォルダーのまま |
| `r` または `F5` | 再分析する。設定も読み直す |
| `c` | クレジットを表示する |
| `Enter` | コレクションのプラットフォーム内: 選択中のゲームについてわかっていることすべて (ウィンドウではダブルクリックでも)。`Enter`、`Esc`、`q` で閉じます |
| `n` | コレクションのプラットフォーム内: 選択したファイルを `ゲームではない` にする (BIOS ファイルなど)、またはそれを解除する |
| `g` | コレクションのプラットフォーム内: プラットフォームの gamelist レポート |
| `e` | ゲーム情報内: ゲームの情報を編集する。`Ctrl+S` で保存、`Esc` で戻る |
| `w` | コレクションのプラットフォーム内: その `gamelist.xml` をデータベースから書き込む (確認の後) |
| `m` | コレクションのプラットフォーム内: その使われていないメディアファイルを削除する (確認の後) |
| `F1` または `?` | すべてのキーを表示する、または隠す |
| `q` または `Esc` | 何も削除せずに閉じる。コレクションのプラットフォームでは、どちらもまず概要に戻る。手動変更の後は先に確認する |

横線がゲームを区切り、ゲームは 1 つおきに濃い灰色の背景になります。`サイズ` 列は各ファイルのサイズを、Windows エクスプローラーと同様に切り上げた KB で表示します (`1,234 KB`)。`?` はサイズを読み込めなかったことを示します。サイズは分析中に読み込まれます。保持するファイルは `保持:` の下に緑の太字で、削除するファイルは `削除対象` の下に赤で表示されます。ウィンドウは黒い背景に白い Lucida Sans Typewriter 11 pt の文字を表示します。このフォントがインストールされていない場合、Windows は黙って代替フォントを選びます。手動で移動したファイルは茶色の背景になり、メモに `手動` と表示されます。行を選択している間は青く表示されます。プログラムのメモは、移動したファイルに関するものであっても変わりません。

`要確認` は問題のないゲームを、`完全に削除` は何かが残るすべてのゲームを隠します。**それらの削除対象ファイルも、削除の実行時には削除されます**。確認画面にその数が表示されます。手動で変更したゲームは、フィルターで隠れない限り常に表示されます。

### フィルター

下部の行の左にあるフィルター欄は、現在の表示を、ファイル名にパターンを含むゲームに絞り込みます。ゲームのファイルの 1 つが一致すれば、そのゲームは全体が表示されます。一覧は入力の少し後に更新されます。ファイルの内容は読み込みません。

- `*` は任意の数の文字、`?` はちょうど 1 文字を表します。`[` と `]` を含むその他の文字はそのまま文字として扱われ、大文字と小文字は区別しません。 先頭と末尾の空白は、引用符で囲んだときだけ数えます: `" by "` は `Mario by Mick` を見つけますが `Moby Dick` は見つけません。引用符なしの `by` は両方を見つけます。
- パターンは名前のどこに現れても構いません: `Beta`、`*Beta*`、`Mario?2` はいずれも `Super Mario 2 (Beta).nes` も見つけます。したがって `S*` は、`S` で始まる名前だけでなく、`S` を含むすべての名前を見つけます。
- `Enter`、`Tab`、下矢印で一覧に戻ります。`Esc` はフィルターを消去して一覧に戻ります。
- カーソルが欄にある間、キーは欄に入力されるだけです: `x`、`k`、`Enter`、`f`、`r`、`F5`、`Esc` は一覧の機能を実行しません。
- フィルターは `F5` の後、削除の後、別のフォルダーを選んだ後も有効なままです。保存はされません。

**フィルターは表示を変えるだけです。フィルターで隠れている削除対象ファイルも、削除を実行すると削除されます**。確認画面にその数が示されます。

### 設定

下の行の `設定...` ボタンまたは `s` は、`redundanz_config.json` でよく変更する項目を、ファイル一覧の代わりにメインウィンドウに表示します。`保存` または `キャンセル`、`Esc`、`Ctrl+E`、または `設定...` をもう一度クリックすると一覧に戻ります。その間、フィルター、表示切り替え、`実行...`、`再分析`、`フォルダー...` はロックされ、隠れた一覧で何も変わらないように `x`、`k`、`Enter`、`F12` は何もしません。

- **言語:** 画面の言語を決めます。 6 つの言語から選びます。新しい言語は次回の起動から適用されます。
- **優先順位:** どの地域版を他より優先するかを決めます。 最も良い地域を上に。`Beta` や `Proto` などの追加情報は `none` の後に置き、そうしたファイルが最後になるようにします (ルール 6)。項目を選んで `上へ` と `下へ` で移動し、`削除` または `Delete` キーで取り除き、一覧の下の欄と `追加` (または `Enter`) で新しい項目を加えます。
- **削除キーワード:** ゲームのどの版を必ず削除するかを決めます。 カンマ区切り。たとえば `Hack, Hacks`。これを含むファイルは削除対象になります (ルール 2)。
- **同じゲームが通常ファイルと ZIP ファイルの両方にある場合:** 両方が同じバージョンのとき、どちらを残すかを決めます。`通常ファイルを保持` (既定) は ZIP ファイルを、`ZIP ファイルを保持` は通常ファイルを削除対象にします ([ZIP ファイル](#zip-ファイル) を参照)。
- **お気に入りとプレイ済みのゲーム (gamelist.xml):** `一覧に注意を出すだけ` (既定) はルールに判定を任せます。削除対象で、`gamelist.xml` によるとお気に入りかプレイ時間のあるファイルには、メモ `お気に入りまたはプレイ済み – 削除されます` が付きます。`優先して残す` は、ゲーム内でお気に入りのファイルを、なければプレイ時間の最も長いファイルを残します。ルールが別の 1 つのファイルを残していた場合はそれが譲り、セーブデータは残すファイルに従います。全般またはプラットフォームごとに適用されます (設定の `prefer_played`)。

`保存` はファイルを書き込み、優先順位、キーワード、通常ファイルと ZIP ファイルの選択が変わった場合はフォルダーを再分析します。手動で削除対象を変更していた場合、その変更は失われるため、プログラムは先に確認します。ファイルのその他の項目はそのまま残ります。空の地域一覧や同じ地域の重複などの誤った値は報告され、何も書き込まれず、設定は開いたままです。ファイルを読み込めない場合、設定は開きません。知らない項目を上書きしないためです。`--config` を使うと設定はそのファイルを編集し、`--priority` を使うと今回の実行ではそこで指定した優先順位が引き続き適用されます。

要確認になるのは、意図せず何かが失われるおそれのある場合だけです。削除キーワードが求めるものは意図どおりであり、内容が保持されるファイルに含まれているファイル (`… と内容が同じ`) は失われません。次の場合、ゲームは要確認とみなされます:

- 削除キーワードが求めていないのに、ファイルが 1 つも保持されない (削除キーワードによって、または ROM のないセーブデータとして完全になくなるゲームは `完全に削除` に表示されますが、要確認ではありません)、
- 削除対象の ZIP の内容が他のどこにもない (`ゲームの内容が保持されるバージョンと異なります`)、
- ZIP が破損している、暗号化されている、または読み込めない、
- ファイルがステータスファイルまたはセーブデータの疑いで保持されている (ルール 9)、
- ルールが `同点` によってのみ判定し、削除対象ファイルの内容が異なる、
- 同じバージョンの複数の ZIP の内容が異なる、
- ファイル名でゲームの表記が異なり (`Title 1-2` と `Title 12`)、保持されるどのファイルとも異なる表記の削除対象ファイルの内容が異なる、
- 削除対象ファイルのファイル形式が保持されるファイルと異なり (`.nes` と `.sfc`)、その内容がどの保持ファイルにも含まれていない。

削除キーワードがファイルを削除対象にした場合、これらのどの場合でも、そのファイルによってゲームが要確認になることはありません。

ウィンドウは `tkinter` を使います。これは Windows の通常の Python インストールに含まれています。ない場合、プログラムはそのことを報告し、何も削除しません。

## 自動整理のあとで

自動整理のあとでも、重複したゲームの版が残っていることがあります。いちばん簡単に見つける方法はフィルターです (キー `/` を押してゲーム名を入力)。そのあと、まだ削除すべきファイルを削除対象にできます。

## ターミナル版 (Linux)

同じプログラムはテキストターミナルでも動作します。たとえば SSH 経由 (PuTTY、MobaXterm)、`tmux` の中、または Linux コンソールです。同じ一覧を表示し、同じルールを適用し、`redundanz_config.json`、`rom_cleanup_workbench_settings.json`、`translations.py` をウィンドウと共有します。

Linux では、グラフィカルな表示がない場合 (SSH 経由のように `DISPLAY` も `WAYLAND_DISPLAY` も設定されていない場合) に自動で起動します。`--tui` を付けると、Windows を含むそれ以外の環境でも起動します。MobaXterm や WSL など、グラフィカルな表示はあってもターミナルを使いたい場合に使ってください。

[Textual](https://textual.textualize.io/) が必要です (8.2.8 で動作確認)。インストールとプログラムの起動方法は [インストール](#インストール) と [使い方](#使い方) を参照してください。

Textual がない場合、プログラムはそのことを伝え、何も削除しません。画面には上から順にウィンドウと同じ行があります: フォルダー付きの緑のタイトル行、主なキー付きのプラットフォーム、一覧、`ゲーム名のみ` スイッチ付きのフィルター欄、4 つの表示切り替え、緑のステータス行です。一覧では各ゲームが太字の名前で始まり、右端まで線が続きます。`名前の表記が異なります` などのメモはこの行に表示されます。PuTTY の 80 桁など幅の狭いターミナルでは、長いファイル名やメモは画面からはみ出さず、その列の中で折り返されます。`やることはありません。` はターミナル自身の点滅機能で点滅します。PuTTY では、点滅テキストを先に有効にする必要がある場合があります。質問とメッセージは一覧の上の枠に、プログラムの言語のボタン付きで表示されます。`いいえ` が既定で選ばれています。

プラットフォームの右に主なキーが表示され、`F1` または `?` ですべてのキーがテーマ別に表示されます。ウィンドウとターミナル版のキーは同じです。

| キー | 効果 |
| --- | --- |
| 矢印キー | 行を選択。Shift で複数行 |
| `Tab` / `Shift+Tab` | 次 / 前のゲーム。その最初のファイルが選択される |
| `x` / `k` | 選択したファイルを削除対象にする / 保持する |

**色と文字。** 256 色以上では、ターミナル版はウィンドウの色を使いますが、各ゲームの背景は黒です (縞模様なし)。ターミナルが 16 色しかない場合 (`TERM=xterm`、`TERM=linux`)、シンプルな ANSI カラーに切り替えます: 青い選択、緑のタイトル行とステータス行、緑の保持ファイルと赤の削除対象ファイル、手動で変更した黒文字の茶色の行です。Linux コンソール、`vt100` などのターミナル、そしてロケールが UTF-8 以外の文字セットを示す場合 (たとえば `en_US` や `de_DE.ISO-8859-1`) は、ASCII 文字だけで描画します: 表示は `(*)`、枠は `+`、`-`、`|` です。`--ascii` でこれを強制できます。PuTTY は `xterm` (16 色) として名乗ります。ウィンドウと同じ色にするには、*Connection → Data → Terminal-type string* を `xterm-256color` にしてください。日本語などの他の文字体系のファイル名やテキストには、引き続きそれを表示できるターミナルとフォントが必要です。

ウィンドウとの違い: フォントはターミナルのものなので、文字の拡大縮小はありません (PuTTY では *Window → Appearance*)。また、ゲームは縞模様ではなく、ハイフンの線で始まります。16 色では緑の行の文字は黒になり、明るい緑の上でも読みやすいままです。削除中、ターミナル版はバックグラウンドで削除し、進行状況バーを表示します。終わるまですべてのキーはロックされます。ウィンドウとターミナル版は、表示と確認済みのセーブデータを同じ `rom_cleanup_workbench_settings.json` に保存します。

## 設定ファイル: `redundanz_config.json`

このファイルはプログラムの隣にあり、分析のたびに読み直されます。言語、優先順位、削除キーワード、通常ファイルと ZIP ファイルの選択は、ウィンドウの `設定...` で変更するのが最も簡単です ([設定](#設定) を参照)。ファイルを直接編集する場合は、`region_priority` の順番を並べ替えて保存するだけで十分です:

```json
"region_priority": ["USA", "Europe", "none", "Japan", "Beta"],
"delete_tags": [],
"prefer_zip": false,
```

ファイルに誤り (たとえばつづりの間違った項目) があると、分析は行われず、何も削除されません。付属のファイルは次のとおりです: 言語は英語、優先順位は USA、Europe、none、Japan、Beta、削除キーワードはなく、ZIP ファイルの隣では通常ファイルが残ります。つまり地域のないファイルは日本のファイルより優先されます。ファイルや項目がない場合も、同じ既定値が使われます。

- `language`: ウィンドウ、メモ、ターミナル出力の言語 (下記参照)。
- `region_priority`: 地域と追加情報。良いものから順に並べます。`none` は地域が不明なファイルを表し、他の言語の語 (`keine`、`nessuna`、`ninguna`、`aucune`、`なし`) も使えます。`none` の後に `Beta` などの追加情報を置くと、そうしたファイルは最後になります (ルール 6)。`Beta` は `Beta 2` にも一致します。
- `region_aliases`: 地域の別表記。たとえば `Europe` に対する `Europa`。`Title (J) [o1].nes` のような GoodTools 名の短縮形 `U`、`E`、`J` も含まれています。
- `delete_tags`: 削除キーワード。常に削除につながる追加情報です (ルール 2)。既定では一覧は空です。削除キーワードは、かっこ内のどこにあっても単語全体として一致します: `Hack` は `(Hack)`、`(Hack 2)`、`(Hack by Someone)`、`(Micks Hack)` に一致しますが、`(Hacks)` や `(Hackers)`、`Hack Attack (USA)` のようにかっこの外にある単語には一致しません。ハックを削除したい場合は、`Hack` と `Hacks` の両方を入力します。
- `part_tags`: バージョンの構成部分。たとえば `Disc 1`。
- `prefer_zip`: 同じバージョンのゲームが通常ファイルと ZIP ファイルの両方にある場合、`false` (既定) は通常ファイルを、`true` は ZIP ファイルを残します。

古いファイルには、最も低い優先度の追加情報である `low_priority_tags` がまだ含まれていることがあります。プログラムはその項目を、`region_priority` の末尾、`none` の後にあるものとして読み込みます。設定は保存時にそこへ移動し、この項目はなくなります。

### 言語

```json
"language": "de",
```

| 値 | 言語 |
| --- | --- |
| `en` | 英語 (既定) |
| `de` | ドイツ語 |
| `it` | イタリア語 |
| `es` | スペイン語 |
| `fr` | フランス語 |
| `ja` | 日本語 |

言語はウィンドウ、メモ、ターミナル出力に適用され、プログラムは起動時にそれを読み込みます: 変更した後はプログラムを閉じて再起動してください。`F5` では言語は切り替わりません。不明な値は、上で説明したとおり設定の誤りとして扱われます。ルールはどの言語でも同じように判定します。テキストは `translations.py` にあります。

日本語の場合、Lucida Sans Typewriter には日本語の文字がないため、Windows は代替フォントで文字を表示します。

## ルール

プログラムが完全に無視するファイルがあります: それらはどこにも表示されず、削除されることもありません。かっことして数えるのは `( )`、`[ ]`、`{ }` で、ゲーム名、優先順位、バージョン、削除キーワードのどれでも同じです。

- 名前が `gamelist` で始まるファイル (大文字と小文字は区別しません)。ROM ファイルではありません。
- 隠しファイル: `.xxx` や `.DS_Store` のようにドットで始まる名前、および Windows の「隠しファイル」属性を持つファイル。

1. 最初のかっこより前のテキストが同じなら、ファイルは同じゲームです。大文字と小文字、スペース、ハイフン、アンダースコアは区別しないので、`Pac-Man` = `Pac Man` = `Pac_Man` = `PacMan` です。そのため `Title 1-2` = `Title 12` にもなります。さらに、`und` = `and` = `&` = `&&`、`Sullivan's` = ``Sullivan`s`` = `Sullivan´s` = `Sullivans` (アポストロフィは区別しません)、単独の語としてのローマ数字 `I`～`IX` と `1`～`9` (`Final Fantasy VII` = `Final Fantasy 7`。`X` 以降はそのままです。`Mega Man X` と `Mega Man 10` は別のゲームだからです)、`The Title` = `Title The` = `Title, The` = `Title` も同じとみなされます。名前の途中にある `The` は区別されます。同様に `vs` = `vs.` = `versus` です。番号付きコレクションなどの名前の前の番号は区別しません: `057 Robocop vs Terminator` = `057 - Robocop vs Terminator` = `Robocop vs Terminator`。名前が数字だけの場合 (`1942`) や数字が語に付いている場合 (`2Fast`) は名前の一部のままです。`4 in 1` と `3 in 1` は別のゲームのままです。この場合、名前は比較によってのみ一致するので、別の表記の削除対象ファイルの内容が保持されるファイルと異なれば、ゲームは要確認とみなされます (`名前の表記が異なります`)。
2. 削除キーワード (`delete_tags`、既定ではなし、たとえば `Hack` と `Hacks`) を含むファイルは、そのゲームの唯一のファイルであっても常に削除対象になります。それでも `k` でそのようなファイルを保持できます。そのときメモは `削除キーワード (Hack) により削除 - 指定どおり` です。そのようなファイルの内容は消すためのものなので、内容に関する警告はありません。例外: かっこに複数の地域があり、その 1 つがちょうど削除キーワードで、別の 1 つが優先順位一覧の地域である場合、そのかっこには削除キーワードが適用されません。`(Japan, USA)` は USA 版でもあります: 削除キーワード `Japan` と一覧の `USA` があれば残り、USA 版として並べられます。`(Japan)` だけのものは引き続き削除対象です。
3. 残ったファイルのうち、`region_priority` で最も良い項目を持つものが保持されます。1 つのかっこ内では最も良い項目が数えられます: `(USA, Japan)` なら 2 つのうち良い方です。複数のかっこにまたがる場合は最も悪いものが数えられます: `(USA) (Beta)` は `Beta` として扱われます (ルール 6)。
4. 同じバージョンのファイルはすべて一緒に保持されます。たとえば `(Disc 1)` と `(Disc 2)`、または `.cue` と `.bin` です。それ以外はすべて削除対象になります。例外: これらのファイルの一部だけに名前の前の番号がある場合 (`073 Batman (USA).sfc` と `Batman (USA).sfc`)、番号付きのものが保持され、それ以外は削除対象になります (`番号付きの名前を優先`)。
5. `region_priority` にない地域は `none` として扱われます。`(Rev 1)` のような情報も同様です。
6. `Beta`、`Proto`、`Alpha` などの追加情報は、`region_priority` の `none` の後に書きます。それを含むファイルは、地域のないファイルよりも後ろ、他のすべてのファイルの後に、一覧の順で並びます: `none, Beta, Proto` なら、Beta は Proto より前です。ゲームにより良いファイルがない場合にだけ保持されます。それらの間では再び地域、次にルール 7 のバージョン、次に追加情報の後の番号で比べます: `Beta 2` は `Beta 1` に、`Beta 1` は番号のない `Beta` に勝ちます。番号は数値として比べます (`Beta 10` は `Beta 9` より上)。負けたファイルにはメモ `古いベータ版` が付きます。
7. 優先順位が同じ場合は、数値として比べて最も高いバージョン番号が勝ちます (`v1.10` は `v1.9` より上)。かっこ内では `v1.1`、`Ver 1.1`、`Version 1.1`、`Rev 1`、`Rev A` が認識され、ゲーム名の中では `Title v1.1` の形だけが認識されます (スペースの代わりに `-` や `_` でも可)。バージョンのないファイルは、バージョンのあるファイルに負けます。地域はバージョンより先に数えられます。
8. その後は、名前の前に番号があるファイル (`Batman` より `073 Batman`)、次に追加情報の少ないファイル、次に ZIP でないファイル (`prefer_zip` では ZIP ファイル)、次にアルファベット順で勝ちます。レポートには `同点` と表示されます。
9. ゲームで最も大きいファイルの 1/4 より小さいファイルは、ルール 3～8 の前に取り分けられ、保持されます: ステータスファイルまたはセーブデータの可能性があるためです。そのため削除されることも、本物の ROM を押しのけることもありません。たとえば `1941.state` が `1941.zip` を押しのけることはありません。メモ列には `ステータスファイルまたはセーブデータの疑い` と表示され、そのゲームは要確認とみなされます。このようなゲームは、ファイルが 1 つも削除対象でなくても `要確認`、`削除対象`、`すべてのゲーム` に表示されます。削除を実行すると、プログラムは残っている疑いのあるファイルをすべて正当なものとして確認します: それらはそのまま残り、引き続き削除されることはなく、`F5` の後や再起動後も `要確認` と `削除対象` に表示されなくなります。確認画面にその数が示されます。プログラムはそれらをパスとサイズとともに `rom_cleanup_workbench_settings.json` に記録します。サイズが変わると、そのファイルは再び疑いの対象になります。何も削除対象になっていない場合、`F12` は何も削除せずにそれらを確認することを提案します。ZIP は展開後のサイズで数えます。同じバージョンの大きな通常ファイルの隣にある小さな通常ファイル (`.bin` の隣の `.cue` など)、最大のファイルと同じ拡張子のファイル (大きな `.nes` の隣の小さな `.nes` は ROM であり、ルール 3 から 8 で判定されます)、`delete_tags` や破損した ZIP のために削除対象になったファイルには適用されません。それでも `x` でファイルを手動で削除対象にできます。典型的な拡張子のセーブデータ (`.srm`、`.sav`、`.eep`、`.mpk`、`.fla`、`.sra`、`.rtc`、`.dsv`、`.mcr`、`.state`、`.state1` …、`.state.auto`、`.st0` …、`.ss0` …) はこのルールの対象外です: エミュレーターは、ROM と (拡張子を除いて) まったく同じ名前のセーブデータしか読み込みません。そのためセーブデータは、保持するファイルがちょうどその名前を持つ場合にだけ残ります。たとえば `Mario Kart 64 (USA).n64` の隣の `Mario Kart 64 (USA).srm` です。それ以外はすべて削除対象になり、`Mario Kart 64 (U) [!].mpk` のような別の地域や別の版のものも同様で、メモ `同じ名前の ROM ファイルがないセーブファイル` が付きます。削除キーワードはセーブデータにも適用されます。
10. 実行時には、削除の後、保持する各ファイルの名前の前の番号が、その後のスペース、ピリオド、ハイフン、アンダースコアとともに取り除かれます: `073 Batman (USA).sfc` は `Batman (USA).sfc` に、`057 - Robocop.md` は `Robocop.md` になります。確認画面には事前に数と例が表示されます。何も削除対象になっていない場合、`F12` は名前の変更についてだけ尋ねます。ゲームに `.cue`、`.gdi`、`.m3u`、`.mds`、`.toc`、`.ccd` ファイルが含まれる場合 (その内容にファイル名が書かれています)、または番号なしの名前がすでに使われている場合は、番号は残ります。確認画面にはこの数も表示されます。ZIP の内容の名前は変更されません。ゲームのタイトル行には、最初の保持ファイルの表記 (`Street Fighter II` または `Street Fighter 2`) で、常に番号なしの名前が表示されます。`k` や `x` でファイルを移すと、タイトルもそれに合わせて変わります。数字が一覧番号とみなされるのは、それが明確な場合だけです: 先頭がゼロの場合 (`057`)、後ろに区切り文字がある場合 (`057 - `、`283. `)、または同じゲームが番号なしでもある場合 (`Dynamite Bowl (J)` の隣の `283 Dynamite Bowl`)。ゲームの番号の 1 つが明確なら、そのゲームのすべての番号が一覧番号とみなされます。それ以外の場合、数字はタイトルの一部であり、ファイル名でもタイトル行でもそのまま残ります: `1080 Snowboarding`、`720 Degrees`。

## ZIP ファイル

すべての ZIP ファイルは、ゲームの唯一のファイルであっても完全に読み込まれます。その内容は SHA-256 でゲームの他のファイルと比較されます。

- **保持するファイルと内容が同じ:** ZIP ファイルは削除対象になり、レポートに同じ内容のファイルが示されます。
- **選択の後に ZIP と通常ファイルが残った場合:** ZIP が `(Disc 1)` のような構成部分を含む唯一のファイルである場合、または読み込めない場合は、内容が異なっていても ZIP は常に削除対象になります。
- **`ZIP ファイルを保持` (`prefer_zip`) の場合:** 逆になります。同じバージョンの読み込める ZIP ファイルの隣では、通常ファイルが削除対象になります (`ZIP ファイルを優先`)。そのファイルの内容が保持される ZIP のどれにも含まれていない場合、レポートには `ゲームの内容が保持される ZIP ファイルと異なります` と表示され、ゲームは問題ありとみなされます (`削除対象の通常ファイルの内容が保持されません`)。読み込めない ZIP は通常ファイルを押し出しません。優先順位は引き続き先に適用されます: 通常の `(USA)` ファイルは `(Japan)` の ZIP に勝ちます。
- **内容の異なる同一バージョンの ZIP が複数:** すべて保持され、レポートでそのことが示されます。
- **削除対象だが、内容がどの保持ファイルにもない:** レポートに `ゲームの内容が保持されるバージョンと異なります` と表示されます。ファイルは削除対象のままです。
- **ZIP の名前に地域やバージョンがない:** ZIP 内のファイルが同じゲーム名であれば、その情報はそれらのファイルから取得されます。
- **破損または暗号化された ZIP:** ゲームの唯一のファイルであっても、常に削除対象になります。暗号化された ZIP の内容は確認しません。
- **ロックされた ZIP または不明な方式 (たとえば Deflate64):** これはファイルの状態について何も示しません。ゲームの通常ファイルがなければ保持され、レポートに示されます。

## Claude Code で開発を続ける

このプログラムはフリーソフトウェアです。リポジトリをクローンし、自分でプログラミングしなくても [Claude Code](https://claude.com/claude-code) で開発を続けられます。このプログラムもそうして書かれました。

1. Claude Code をインストールします。Claude のサブスクリプションまたは Claude API のアカウントが必要です。Windows では PowerShell で:

   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```

   Linux では:

   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```

2. リポジトリをクローンし、その中で Claude Code を起動します:

   ```bash
   git clone https://github.com/arved9926/rom-cleanup-workbench.git
   cd rom-cleanup-workbench
   claude
   ```

3. 何を変えたいかを自分の言葉で説明します。たとえば "ZIP ファイルだけを表示するオプションを追加して"。Claude Code はコードを読んで変更を提案し、ファイルを変更したりコマンドを実行したりする前に確認します。そのあとテストを実行させ (フォルダー `Rom Cleanup Workbench` で `python -m unittest`)、変更をコレクションのコピーで試してください。

これまでの変更の計画は `docs/` にあります。変更を配布する場合は、それも GPL のもとで公開する必要があります。
